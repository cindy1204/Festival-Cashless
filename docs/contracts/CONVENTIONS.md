# Common conventions for all modules

The official tests verify exactly what this document says. If your API responds differently, the test fails even if it "works".

## 1. Startup

- `npm run dev` starts the API on the port defined by the environment variable **`PORT`** (default `3000`).
- The database connection comes from **`DATABASE_URL`** in the `.env` file.
- All routes begin with **`/api`**.

## 2. Response format

| Case | Status | Body |
|---|---|---|
| List | `200` | `{ "pagination": { "total", "currentPage", "limit", "totalPages" }, "data": [ ... ] }` |
| A single record (GET by id, PATCH) | `200` | `{ "data": { ... } }` |
| Create | `201` | `{ "data": { ... } }` with the created record, **including its `id`** |
| Delete | `200` | any JSON, such as `{ "message": "..." }` |
| Special non-paginated endpoints | `200` | `{ "data": [ ... ] }` or `{ "data": { ... } }` depending on the contract |
| Any error | `4xx` / `500` | `{ "error": "descriptive message" }` |

- JSON field names match the database column names exactly (`asistente_id`, `hora_inicio`), as generated by `prisma db pull`.
- The stack trace is never returned.

## 3. Pagination

- Optional `page` and `limit` parameters. Defaults are `page=1` and `limit=10`.
- Both must be **positive integers**; `limit` max is **50**. `limit=0`, `page=-1`, `limit=abc`, or `limit=51` → **400**.
- `totalPages = ceil(total / limit)`.
- Lists are ordered by `id` ascending and **exclude** records with `state = 'REMOVED'`.
- Numeric filters such as `?dia_id=` that are not numbers → **400**.

## 4. IDs and existence

- An `:id` that is not a positive integer (`/api/boletas/abc`) → **400**.
- An id that does not exist, or exists with `state = 'REMOVED'` → **404** (in GET, PATCH, and DELETE).
- Deleting the same record twice: the second time → **404**.

## 5. Validation order

When a request has multiple issues, the **first** one in this list is returned:

1. **400** — missing fields, incorrect types, invalid formats, values outside the allowed range or list.
2. **404** — a referenced id does not exist (attendee, show, zone...).
3. **400** — a value exists but is not valid for this module (for example, a zone that is not a parking zone).
4. **409** — a business rule is violated.

## 6. Formats

| Data | Format | Example |
|---|---|---|
| Time | `HH:MM`, 24-hour format, with leading zero | `09:00`, `21:30` |
| Date | `YYYY-MM-DD` | `2026-11-20` |
| Money | integer in pesos, no decimals | `250000` |
| Integers | JSON integer, not text | `"dia_id": 1`, not `"dia_id": "1"` |

## 7. Create, edit, and delete

- **POST:** calculated fields (`precio`, `total`, initial `estado`) are set by the server; if the client sends them, they are ignored.
- **PATCH:** only accepts fields marked as *editable* in your contract. Any field that cannot be edited → **400**. Business rules are rechecked against the combined data.
- **DELETE:** is a **logical delete**: `state` is set to `'REMOVED'`; the row is not removed.

## 8. The database is shared

- All teams in both courses use the **same database**. No one creates tables.
- **Never run `prisma migrate` or `prisma db push`.** Use only `npm run sync` (`prisma db pull` + `prisma generate`). A `migrate` can delete other teams' tables.
- **Only write to your module's tables.** Reading other teams' tables is allowed.
- Do not modify the preloaded data manually: the tests depend on it. To experiment, create your own records and delete them.
